# 游戏策划文档神器 - 系统架构总结

## 核心理念

**AI驱动的长链条文档撰写工具**，核心价值是通过深度访谈、多轮迭代和实时审阅来**提升文档质量**。

## 核心工作流

### 阶段1: 访谈 (Interview)
```
用户启动 → 深度访谈 → 生成结构化总结
         ↓
    理解需求 + 关键决策 + 写作方向
```

### 阶段2: 写作 (Writing) - 核心创新
```
生成大纲 (10章节)
    ↓
┌───────────────────────────┐
│  for each 章节:           │
│    1. 检查Mail            │  ← 用户可实时发送Mail
│       - 紧急: 必查        │
│       - 普通: 自主判断    │
│    2. 处理Mail            │
│       - Opinion: 影响写作 │
│       - Comment: 修改章节 │
│    3. 撰写章节            │
│    4. 保存进度            │
└───────────────────────────┘
    ↓
完整文档 (中文 + Mermaid图表)
```

### 阶段3: 审阅 (Review) - 质量保证
```
┌─────────────────────────────┐
│  审阅迭代 (最多3轮):        │
│    1. 四维度审阅            │
│       - 内容逻辑            │
│       - 内部一致性          │
│       - 行业最佳实践        │
│       - 实施可行性          │
│    2. 分级问题              │
│       - Critical: 立即修复  │
│       - Major: 立即修复     │
│       - Minor: 保留         │
│    3. 自动修复              │
│    4. 再次审阅              │
└─────────────────────────────┘
    ↓
没有Critical/Major → 通过！
```

## 核心创新点

### 1. Mail机制 ⭐⭐⭐
**问题**: 传统AI工具是"一次性生成"，用户无法在过程中干预

**解决**: Mail系统让用户在Agent工作时实时发送指令

- **紧急邮件**: 每轮必查（如"停止"命令）
- **普通邮件**: Agent自主判断是否采纳
- **Opinion**: 加入对话历史，影响后续写作
- **Comment**: 带文本范围指针，精确修改特定段落

**价值**: 将"生成器"变成"协作伙伴"

### 2. 多轮迭代写作
**问题**: 一次性生成长文档容易失控，质量难保证

**解决**:
- 先生成大纲（结构化）
- 逐章节撰写（可控）
- 每轮检查Mail（可干预）
- 实时保存（可恢复）

**价值**: 长链条可控，质量可追溯

### 3. 审阅闭环
**问题**: 审阅只发现问题，不解决问题

**解决**:
- 自动修复Critical/Major问题
- 多轮迭代直到通过
- Minor问题保留（避免过度修改）

**价值**: 真正的质量提升，不只是问题列表

### 4. 渐进式上下文（设计完成，待实现）
**问题**: 加载全部文档会污染上下文

**解决**:
- 先加载摘要
- 发现问题时加载全文
- 用完清理

**价值**: 高效利用上下文窗口

## 关键设计决策

### 1. 为什么选择TypeScript？
- 后续VS Code插件可复用代码
- 类型安全，适合复杂状态管理
- 生态丰富

### 2. 为什么选择Mermaid？
- LLM原生支持，生成质量高
- Markdown原生集成
- VS Code内置预览
- 覆盖大部分需求（流程图、状态图、类图等）

### 3. 为什么不用Excalidraw/SVG？
- LLM生成SVG路径质量差
- Excalidraw需要额外工具链
- 增加复杂度，收益低

### 4. 为什么分章节写作？
- 可控性：每章独立，易于调试
- 可干预性：每轮检查Mail
- 可恢复性：实时保存进度
- 上下文效率：避免一次性加载过多内容

### 5. 为什么只修复Critical/Major？
- Minor问题通常是细节优化，不影响核心质量
- 避免过度修改导致风格变化
- 节省API调用成本

## 性能特征

### API调用次数（典型10章节文档）
- 访谈: 5-10次（取决于对话轮数）
- 写作: 11次（1次大纲 + 10次章节）
- 审阅: 3-9次（1-3轮审阅 + 修复）

**总计**: 约20-30次API调用

### 时间估算
- 访谈: 5-10分钟（人工交互）
- 写作: 5-10分钟（10章节）
- 审阅: 5-15分钟（1-3轮）

**总计**: 15-35分钟
